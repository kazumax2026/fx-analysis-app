# fx-compass-api：5分足OHLC接続仕様（未有効化）

この文書は変更仕様です。現在のWorkersは未変更・未検証です。公開URLは未提供のため推測しません。利用許諾確認前は実データ表示を有効にしません。

## 現状と必要な変更

現在の価格・SMA5・SMA20・BUY/SELL/WAITだけでは、ローソク足、RSI、MACDの計算に必要な履歴がありません。既存エンドポイントを残し、新たに `GET /v1/candles?pair=USDJPY&timeframe=5m` を追加する案です。既存の計算値からOHLCを捏造しません。

通貨は USDJPY / EURJPY / GBPJPY、時間足は5mのみ。Twelve Dataには通貨をUSD/JPY形式、interval=5min、UTC時刻指定で送信します。確定足300本を目標に取得し、形成中の足を除外します。配信仕様に確定フラグがない場合はUTC開始時刻＋5分と配信遅延・反映待ちを考慮します。追加の取得本数は契約上の履歴制限を確認して決めます。

## 成功JSONの契約

| 項目 | 型・意味 |
| --- | --- |
| schemaVersion | 数値1 |
| source | 文字列 twelve-data |
| pair | USD/JPY、EUR/JPY、GBP/JPY |
| timeframe | 文字列5m |
| fetchedAt | 上流取得成功時のUTC epochミリ秒。キャッシュを返す時に書き換えない |
| expiresAt | 更新期限のUTC epochミリ秒。fetchedAtより後、最大10分以内 |
| stale | 真偽値。上流更新失敗・期限切れならtrue |
| marketStatus | open / closed / unknown。根拠がなければunknown |
| delaySeconds | 任意。配信元の既知の遅延秒数。分からなければnull。足の経過時間を流用しない |
| candles | 昇順OHLC配列、目標300本、最大1000本。判定には最低34本必要 |

各足は `{time, open, high, low, close, complete}`。timeはUTC epochミリ秒・5分境界。価格は有限の正の数値。completeはtrueのみ。timeは重複なしの昇順で、time+300000 <= fetchedAt。高値は始値・終値以上、安値は始値・終値以下。Twelve Dataの文字列価格をWorkersで厳密に数値化します。タイムゾーンのない日時をSafariのDate.parseへ渡しません。

休場の空白はそのまま残し、人工的な足を埋めません。休場時でも期限切れデータを現在の判定として扱わず、休場情報を別に表示します。未提供の遅延や市場状態を推定で断定しません。市場開場中に最新足が配信元の既知の遅延・反映待ちを超えて古い場合は、取得通信が成功してもstale=trueにします。fetchedAtが新しいことだけでデータの鮮度を保証しません。

## エラー

不正パラメーター400、アクセス拒否401/403、回数上限429（Retry-After）、上流障害502、タイムアウト504。本文は安全なコードと日本語説明のみ。Twelve DataがHTTP 200の本文で返すエラーも検出します。上流のURL・APIキー・生エラー本文を返しません。

更新失敗時に前回のOHLCを返す場合、元のfetchedAt・expiresAtを保持してstale=true。期限を延長して最新データに見せません。フロントはチャートを参考表示してもサインは「判定不可」にします。

## セキュリティ・運用（Workers側で必要）

- Twelve DataのキーはCloudflare Workers Secretへ保存。公開ソース、ブラウザー、URLログに記録しない。
- Twelve Dataの公開表示・再配布・キャッシュ・保存・帰属表示の条件と契約プランを確認するまでは、Workers側も公開OHLC提供を無効にする。フロントのフラグはアクセス制御ではない。
- 実際のPagesオリジンのみCORS許可。CORSだけでは利用制限できない。匿名APIとして提供するなら明示的にリスクとライセンスを確認する。
- 現在のクライアント準備コードはcredentials=omitで、認証未実装。個人用ログイン保護を採用する場合は、Access・同一サイト構成・Safariの認証を設計してからクライアント側も変更する。共有トークンをJSに埋め込まない。
- 通貨・時間足・取得本数・上流URLを固定し、任意URL中継を禁止。
- 通貨×5mでキャッシュ共有。足の更新時刻＋反映待ちで更新し、同時取得をまとめる。キャッシュ応答でも取得時刻を保持。
- 利用者/IP単位の制限に加え、上流の分・日クレジット予算を全体管理。地域ごとに独立したエッジキャッシュだけに依存せず、必要ならDurable Objects等で共有制御。
- 3通貨を5分ごとに24時間更新すると最大864回/日。実際は選択時のみ取得し、休場も考慮。クレジット換算は契約で確認。

## フロントの有効化条件

`src/data-source.js`のLIVE_CONFIGはenabled=false、licenseApproved=false、endpointは空文字のまま。URLは公開情報だけを指定し、クエリや認証情報を含めない。上記契約のWorkers応答、API保護、Twelve Dataの許諾、Safari実機検証が揃ってから別の変更で有効化する。

現在はサンプルが既定で、実データボタンは無効。許諾後の実装では5mのみ実データ対応、他時間足は「実データ未対応」。選択通貨・時間足を切り替えると通信を取消し、遅い応答を無視。失敗時にサンプルへ自動切替しない。

今回の接続準備は手動「再取得」と15秒ごとの期限チェック。自動取得は未実装。必要なら許諾・予算確認後に、5分足境界と反映待ちを考慮した更新を追加する。Safariから復帰した際の再取得もその段階で確認する。
